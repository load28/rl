# 설계: rl 컴파일러 Rust 재작성

2026-08-16 · 브레인스토밍 세션 결과를 반영한 설계 문서.

> **참고**: 이 문서의 모듈 배치(`transform.rs` 단일 패스)는 역사적 기록이다.
> 현재 구조는 [`compiler-architecture.md`](./compiler-architecture.md)의
> 단계 분리 파이프라인(ast / parser / sema / codegen)이 규범이다 (TASK-010).

## 배경

v0.1은 의존성 없는 JavaScript(Node)로 구현되어 언어 스펙을 검증했다:

- `.rl`은 TypeScript의 상위집합 — 유효한 TS는 바이트 단위 그대로 통과
- `variant` → 태그드 유니언 타입 + 생성자 객체
- `match` → `kind` 판별 `switch` IIFE, `_` 없으면 `never` 검사로 tsc가 소진성 보장
- 테스트 35개 (패스스루 14, 컴파일 출력, 런타임, tsc 타입체크)

이번 단계는 컴파일러 구현체를 Rust로 옮기는 것이다. 언어 스펙은 변경하지 않는다.

## 핵심 제약: rl 구문은 유효한 TS가 아니다

`variant Shape { ... }`와 `match (x) { A => 1 }`은 TS 문법이 아니므로, swc(또는
oxc)에 `.rl` 파일을 통째로 넘기면 파싱 자체가 실패한다. 파서를 포크해 문법을
추가하는 길은 유지보수 비용이 과도해 배제했다. 따라서 역할을 나눈다:

- **rl 구문 탐지·변환**: v0.1에서 검증된 자체 스캐너 알고리즘(문자열·템플릿·주석·
  정규식 인식 스캔 + 구문이 완전히 파싱될 때만 변환, 아니면 원문 통과)을 Rust로
  이식한다. 이 알고리즘이 "모든 유효한 TS는 유효한 rl" 보장의 근간이다.
- **swc (`swc_ecma_parser`)의 역할**:
  1. **조각 검증** — `variant` 필드 타입처럼 순수 TS인 조각을 파싱해, 잘못된
     타입 표기를 rl 컴파일 시점에 정확한 `.rl` 위치와 함께 거부한다.
  2. **출력 검증** — 최종 생성된 TS 전체를 파싱해 컴파일러가 잘못된 코드를
     내보내는 버그를 자가 검사한다. `--no-verify`로 끌 수 있다 (swc가 아직
     모르는 최신 TS 문법을 쓰는 패스스루 코드를 위한 탈출구).

oxc가 아닌 swc를 택한 이유: 독립 크레이트로 쓰기에 API가 안정적이고 문서가
많다. oxc는 아레나 할당자 수명과 잦은 breaking change로 임베딩 비용이 더 크다.

## 아키텍처

```
src/
  lib.rs        공개 API: compile(source, options) -> Result<String, CompileError>
  error.rs      CompileError { message, filename, line, col }
  scanner.rs    바이트 단위 저수준 스캔 (문자열/템플릿/주석/정규식/괄호 짝)
  transform.rs  메인 변환 루프 + variant/match 파싱 + TS 코드 방출
  verify.rs     swc 기반 조각·출력 검증
  main.rs       rlc CLI (파일/디렉터리, --print, --out-dir, --check, --no-banner, --no-verify)
tests/
  passthrough.rs  유효 TS 바이트 단위 보존 (JS판 테스트 이식)
  compile.rs      방출 코드·에러 케이스 (JS판 테스트 이식 + 에러 위치 검증)
  integration.rs  tsc 타입체크·소진성 검사·node 런타임 실행 (tsc 없으면 스킵)
```

### JS판 대비 구조 개선: 절대 오프셋

JS판은 재귀 시 부분 문자열을 잘라 넘겨 원본 위치를 잃었다. Rust판은 항상 전체
소스에 대한 `(start, end)` 범위로 재귀해, 모든 파스 지점이 절대 오프셋을 유지한다.
덕분에 에러(중복 케이스, 와일드카드 위치, 잘못된 필드 타입 등)가 전부
`파일:행:열`로 보고된다.

### 인코딩

스캐너는 바이트(`&[u8]`) 단위로 동작한다. 의미 있는 문자는 전부 ASCII이고,
UTF-8 연속 바이트(0x80+)는 어떤 ASCII 비교와도 일치하지 않으므로 멀티바이트
문자는 자연스럽게 불투명하게 통과한다. 출력은 원본의 유효한 슬라이스 재조합이므로
UTF-8 유효성이 보존된다.

## 방출 코드 호환성

생성되는 TypeScript는 JS판 v0.1과 문자 단위로 동일하게 유지한다. 근거:
이식 검증을 "기존 커밋된 `examples/shapes.ts`와 diff 없음"으로 환원할 수 있고,
기존 테스트의 기대값을 수정 없이 이식할 수 있다.

## 테스트 전략

1. JS판 테스트 35개 전량을 Rust 테스트로 이식 (패스스루/방출/에러/타입체크/런타임).
2. 에러 위치(행:열) 검증 테스트 신규 추가.
3. swc 검증 동작 테스트 신규 추가 (잘못된 필드 타입 거부, 출력 자가 검증).
4. 통합 테스트는 `tsc`/`node` 부재 시 스킵 (CI 아닌 환경 배려).
5. 마지막에 `examples/shapes.rl`을 Rust CLI로 재생성해 기존 산출물과 diff 비교.

## 삭제 계획

Rust 테스트가 전부 통과하고 examples 산출물 diff가 깨끗한 뒤에만
`src/compile.js`, `bin/rlc.js`, `test/`, `package.json`을 제거한다.
