## 목적

TypeScript의 타입 추론이 Rust에 미치지 못하는 지점들을 tsc 실측으로 분류하고,
그중 rl이 — `match`처럼 런타임 코드를 방출하는 구문을 포함해 — 메울 수 있는
것들을 기능 제안으로 정리한다. 이 태스크는 **제안 문서 작성**까지이며, 개별
제안의 구현은 승인 후 별도 태스크로 진행한다 (TASK-013 선례).

  `if let` / `is` 패턴)의 문법·판별·소진성·방출 스케치, 전처리로 못 메우는
  한계 목록, 우선순위 권고.
- 제외: 컴파일러 구현, 레퍼런스 문서(`docs/reference/`) 갱신 — 전부 승인 후

## 의사결정

### 결정 1: 격차를 [B]이미 메움 / [P]제안 / [C]불가로 3분류

- **상황**: "추론이 안 되는 부분"의 나열만으로는 제안이 되지 않는다 —
  rl이 손댈 수 있는 것과 없는 것의 경계가 필요했다.
- **검토한 대안**: (A) TS 추론 한계 전체 나열 — 후방 추론·정수 타입처럼
  전처리로 불가능한 항목이 제안처럼 읽혀 오해 유발. (B) 설계 계약(타입을
  모르는 rlc / 방출 코드는 tsc 에러 금지 / 통과 계약)을 판단 기준으로 먼저
  세우고 3분류.
- **선택과 근거**: (B). 계약이 이미 CLAUDE.md에 있으므로 기준 신설이 아니라
  적용이고, [C] 목록을 정직하게 남겨 이후 범위 밖 요청의 안내 근거가 된다.

### 결정 2: 모든 격차 주장을 tsc 6.0.2 실측으로 뒷받침

- **상황**: TS 추론 한계에 대한 통념은 버전에 따라 틀린다(예: TS 5.5의
  filter 술어 추론). 통념 기반 제안은 근거가 무너질 수 있다.
- **검토한 대안**: (A) 문헌/기억 기반 서술 — 빠르지만 검증 불가.
  (B) 격차마다 최소 재현을 만들어 `tsc --strict --noEmit`로 에러를 실측하고
  에러 코드를 문서에 그대로 인용.
- **선택과 근거**: (B). TASK-013이 커링 붕괴를 실측으로 걸러낸 선례를 따랐고,
  실제로 두 통념이 실측에서 깨졌다(이슈 1·2) — 실측 없이 썼으면 틀린 문서가
  됐다.

### 결정 3: 최우선 제안은 튜플 match (곱집합 소진성)

- **상황**: 제안 5건의 우선순위가 필요했다.
- **검토한 대안**: 각 제안을 "TS로 대체 가능한가 × rlc 구조 검사와 맞는가 ×
  구현 신설량"으로 비교. 중첩 패턴·if let은 기존 기계 재사용으로 싸지만
  조건 체인/let-else로 어느 정도 대체 가능. 리터럴 패턴은 `_` 필수 제약
  하에서 이득이 작음. 튜플 match의 곱집합 소진성만이 TS로 재현 불가.
- **선택과 근거**: 튜플 match. "TS가 어떤 트릭으로도 못 하는 것"이 rl의
  존재 가치와 직결되고, 소진성이 타입 정보 없는 순수 태그-곱 구조 검사라
  rlc 제약과 정확히 맞는다.

### 결정 4: `match (a, b)` 재해석은 암 패턴 주도로 (하위호환)

- **상황**: `match (a, b)`는 현재도 콤마 식 스크루티니로 파싱된다 — 튜플
  match 도입 시 기존 .rl 의미가 바뀔 수 있다.
- **검토한 대안**: (A) 스크루티니의 최상위 콤마를 무조건 튜플로 — 기존
  콤마 식 사용 파손. (B) 암에 튜플-패턴이 하나라도 있을 때만 튜플 match로
  해석 — 기존 프로그램 의미 불변, 판별이 구조 파싱 범위 안.
- **선택과 근거**: (B). 통과 계약과 별개로 "기존 rl 프로그램의 의미 불변"도
  지킬 수 있으면 지키는 쪽이 맞고, 판별 비용이 없다.

### 결정 5: 리터럴 패턴 소진성은 `_` 필수 (never 센티널 기각)

- **상황**: rlc는 타입을 몰라 리터럴 유니언의 전체 집합을 알 수 없다.
  `default`에 `const $rl_x: never = $rl_m;`을 방출하면 tsc가 누락을 잡지만,
  "방출 코드가 tsc 에러를 만들면 안 된다"는 계약 2를 정면으로 깬다.
- **검토한 대안**: (A) `_` 암 필수(구조로 강제 가능) — 소진성은 포기하되
  계약 유지. (B) never 센티널 opt-in — 계약 개정 선행 필요, 에러 위치가
  생성물 기준이 되는 부작용.
- **선택과 근거**: (A). 계약 개정은 이 제안 하나로 정당화하기에 크다.
  (B)는 [C] 목록에 "계약 개정이 선행 조건"으로 명시해 후일 판단거리로 남김.

### 결정 6: 중첩 패턴 소진성은 보수적 v1 (커버 불인정)

- **상황**: `Ok(value: Some(v))` 암이 외부 태그 `Ok`를 커버한다고 인정하면
  내부 `None` 누락이 안 잡히고, 내부 곱 소진성 검사는 검사기 구조 변경이 크다.
- **검토한 대안**: (A) 중첩 암은 가드 암과 동일하게 커버 불인정 — 기존 검사
  규칙에 자연 편입, 오류 방향이 "빠졌다고 잘못 보고"(안전). (B) 외부 태그별
  내부 태그 집합까지 검사 — 정확하나 v1 범위 초과.
- **선택과 근거**: (A)를 v1로, (B)는 구현 경험 후 v2로 명시. 가드의 기존
  선례("가드 암은 케이스를 커버하지 못한다")와 의미가 같아 사용자 모델이
  일관된다.

## 이슈 및 해결

### 이슈 1: 후방 추론 재현 1차 시도가 에러를 내지 않음

- **증상**: `const xs = []; xs.push(1); const n: number = xs[0];`가 strict에서
  에러 없이 통과 — "빈 배열은 추론 안 됨" 통념으로 만든 재현이 실패.
- **원인**: TS의 evolving array 특례 — `[]`로 초기화된 지역 변수는 이후
  push로 원소 타입이 진화한다. 통념이 이 특례를 놓친 것.
- **해결**: 격차의 본질은 배열이 아니라 **제네릭 호출 시점의 즉시 붕괴**임을
  확인하고 재현을 교체 — `function make<T>() {...}; const ys = make();`에서
  `T = unknown`으로 즉시 확정, 이후 `push(1)`이 소급되지 않음(TS2322 실측).
  evolving array도 제네릭 함수 인자로 넘기면 특례가 깨짐(TS7005)을 병기.

### 이슈 2: await/함수 호출이 내로잉을 소실시킨다는 통념이 실측에서 깨짐

- **증상**: `if (x.v === null) return; await ...; x.v.length;`가 에러일 것으로
  예상했으나 tsc 6.0.2에서 통과. 무관한 함수 호출 뒤에도 통과.
- **원인**: TS는 프로퍼티 내로잉을 호출/await 경계에서 리셋하지 않는다
  (건전성을 희생한 편의 — 호출이 실제로 x.v를 변이해도 좁힘 유지). 소실되는
  경계는 클로저(TS18047)와 이후 재할당이 있는 `let`뿐.
- **해결**: 문서의 G5를 실측대로 서술("통념보다 낫다 — 소실은 클로저
  경계")로 고치고, rl의 완화 원칙(구문의 const 물질화)과 `if let` 제안의
  근거를 클로저 경계로 한정했다.

### 이슈 3: 검증 게이트에서 `cli_types_without_typescript_says_so` 실패

- **증상**: `cargo test` 중 해당 테스트가
  `expected failure: rlc: src/level.rl → .rl-types/level.rl.d.ts`로 패닉 —
  "typescript 없음" 실패를 기대했는데 rlc가 성공했다. 본 태스크는 문서
  변경뿐이므로 변경과 무관한 실패.
- **원인**: rlc의 `src/types_host.mjs`는 `require("typescript")` 실패 시
  **PATH의 `tsc`가 속한 패키지로 폴백**해 전역 TypeScript를 찾는다
  (`globalTypescriptBases`). 그런데 테스트의 스킵 가드
  `global_typescript_resolvable()`은 `node -e 'require("typescript")'`만
  확인한다. 이 컨테이너(tsc는 `/opt/node22/bin`에 있으나 모듈은 node 기본
  해석 경로 밖)에서는 가드가 false를 돌려 스킵을 놓치고, rlc는 폴백으로
  성공한다 — 가드가 rlc의 실제 해석 규칙보다 좁았던 기존 버그.
- **해결**: 가드에 두 번째 확인을 추가 — `require` 실패 시 PATH 항목들에서
  `tsc`/`tsc.cmd` 존재를 검사해, 폴백으로 성공하는 환경도 스킵하도록
  `tests/integration.rs`를 수정. 수정 후 해당 테스트가 스킵되고 전체
  게이트가 통과함을 확인.
