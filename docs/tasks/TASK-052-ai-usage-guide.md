## 목적

사용자가 AI 코딩 도구(Claude Code, Cursor, Copilot 등)로 rl 프로젝트를
구축·개발할 때, AI가 rl 문법과 규칙을 올바르게 쓰도록 가르치는 컨텍스트
문서를 제공한다. 기존 레퍼런스(`docs/reference/`)는 사람이 읽는 규범 문서라
분량이 크고 네 파일로 나뉘어 있어, AI 컨텍스트에 그대로 넣기에 적합하지 않다.

## 범위

- 포함: AI 컨텍스트용 자기 완결 가이드(`docs/ai/rl.md`), 각 AI 도구에
  연결하는 방법 안내(`docs/ai/README.md`), README·CLAUDE.md의 문서 맵 갱신.
- 제외: 언어 표면 변경 없음(레퍼런스 갱신 불필요). llms.txt 표준 채택,
  npm 패키지에 문서 동봉, 에디터 확장 연동은 이번 범위 밖 — 필요해지면
  별도 태스크로.

## 의사결정

### 결정 1: 산출물 형태 — 단일 자기 완결 Markdown 컨텍스트 파일

- **상황**: "AI에게 rl을 가르친다"를 어떤 형태로 제공할지 정해야 했다.
- **검토한 대안**:
  - A. 레퍼런스 네 파일을 그대로 쓰라고 안내만 — 추가 문서 없음. 유지 비용
    0이지만 분량이 크고(언어 레퍼런스만 660여 줄) 한국어라 도구·모델에 따라
    정확도가 떨어질 수 있으며, AI에게 필요 없는 내용(방출 상세, 도구 모드)이
    많다.
  - B. 루트 `llms.txt` 표준 채택 — 링크 목록 형태라 결국 링크를 따라가 원문을
    읽어야 하고, 사용자 프로젝트에 복사해 쓰는 흐름과 맞지 않는다.
  - C. `docs/ai/rl.md` 단일 자기 완결 파일 — 사용자 프로젝트에 복사해
    CLAUDE.md/AGENTS.md/Cursor rules 어디에나 넣을 수 있고, 컨텍스트 예산에
    맞게 압축·선별할 수 있다. 레퍼런스와 이중화되는 유지 비용이 생긴다.
- **선택과 근거**: C. 실제 사용 흐름(사용자 프로젝트의 AI 컨텍스트에 주입)에
  맞는 유일한 형태다. 이중화 부담은 README.md(docs/ai)에 "레퍼런스가 바뀌면
  함께 갱신, 어긋나면 버그" 규칙을 명시해 CLAUDE.md의 기존 문서 갱신 규칙과
  같은 방식으로 관리한다.

### 결정 2: 가이드 본문은 영어, 안내문은 한국어

- **상황**: 저장소 문서는 전부 한국어인데, 가이드의 소비자는 다양한 AI
  도구·모델이다.
- **검토한 대안**: 한국어(저장소 일관성) / 영어(도구·모델 호환성) / 병기
  (분량 2배 — 컨텍스트 낭비).
- **선택과 근거**: 본문(`rl.md`)은 영어 — 컨텍스트 파일은 모델이 직접 읽는
  입력이고, 영어가 모든 코딩 AI에서 가장 안정적으로 해석된다. 사람이 읽는
  사용 안내(`docs/ai/README.md`)는 저장소 관례대로 한국어.

### 결정 3: 내용 선별 기준 — "AI가 실제로 틀리는 것" 중심

- **상황**: 레퍼런스 전체를 압축하면 여전히 길다. 무엇을 남길지 기준이
  필요했다.
- **검토한 대안**: 레퍼런스 축약 전문(망라적, 길다) / 치트시트만(짧지만
  함정 설명이 빠져 AI가 통과 계약을 모른 채 틀린다).
- **선택과 근거**: AI 실수 유발 지점을 우선했다: ① 어긋난 rl 구문은 에러가
  아니라 **조용히 통과**된다는 계약(그리고 `if let`·`|>`만 예외), ② 리터럴
  패턴 없음, ③ 이름 기준 바인딩, ④ 가드/중첩 암은 소진성 커버 불인정,
  ⑤ 필수 세미콜론·괄호, ⑥ `try`/let-else 위치 제약, ⑦ std 필드명
  `value`/`error`. 방출 코드 상세·도구 모드(`--symbols`/`--emit-map` 등)는
  AI가 코드를 쓰는 데 불필요해 제외했다. 마지막에 10항목 체크리스트를 둬서
  긴 컨텍스트에서도 규칙이 회수되도록 했다.
