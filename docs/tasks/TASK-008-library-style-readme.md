## 목적

기존 README는 언어 기능을 위에서 아래로 서술하는 튜토리얼/명세 혼합 문서였다.
오픈소스 라이브러리의 표준 README 구조(태그라인 → 배지 → 한눈에 보이는 예제 →
특징 → 설치 → 빠른 시작 → 사용법 → 문서 링크 → 제한사항 → 기여/라이선스)로
재작성해, 처음 방문한 사람이 "무엇인지 → 어떻게 설치하는지 → 어떻게 쓰는지"를
순서대로 파악할 수 있게 한다.

## 범위

- 포함: `README.md` 전면 재작성 (구조 개편, 배지 추가, 내용 재배치·요약).
- 제외: `docs/reference/` 등 규범 문서 변경 없음 — 언어 표면(구문, 규칙,
  방출 코드, 에러, CLI)은 전혀 건드리지 않는다. README에서 상세 설명은
  레퍼런스로 링크만 한다.

## 의사결정

### 결정 1: 라이브러리 표준 README 구조 채택

- **상황**: 기존 README는 도입부 직후 핵심 원칙 2개와 문서 목록이 나오고,
  기능 설명이 명세 수준으로 길게 이어져 라이브러리 첫인상 문서로는 부적합했다.
- **검토한 대안**:
  - A. 기존 구조 유지 + 문장만 다듬기 — 근본 문제(구조)가 해결되지 않음.
  - B. 영어로 전환 + 표준 구조 — 저장소의 모든 문서(CLAUDE.md, 레퍼런스,
    태스크)가 한국어라 일관성이 깨짐.
  - C. 한국어 유지 + 표준 라이브러리 구조로 전면 개편 — 일관성과 구조를
    모두 확보.
- **선택과 근거**: C. 저장소 문서 언어 관례(한국어)를 따르면서, 특징/설치/
  빠른 시작/사용법/문서/제한사항/기여/라이선스 순의 관례적 구조를 적용했다.

### 결정 2: 상세 명세는 레퍼런스로 위임하고 README는 요약만

- **상황**: 기존 README에 있던 TS enum 판별 규칙 전문, 소진성 검사 알고리즘
  상세, swc 검증 구조 설명 등을 그대로 둘지 결정 필요.
- **검토한 대안**:
  - A. 전부 유지 — README가 길어져 라이브러리 README의 역할(빠른 파악)을 해침.
  - B. 핵심 요약 + `docs/reference/` 링크 — 규범 문서가 이미 존재하므로 중복
    없이 역할 분리가 됨.
- **선택과 근거**: B. `docs/reference/language.md` 등이 규범 문서로 이미
  존재하고 CLAUDE.md도 "레퍼런스가 규범"이라 명시하므로, README는 요약과
  링크만 담당하게 했다.

### 결정 3: 배지는 CI·라이선스·Rust 버전만

- **상황**: 라이브러리 README 관례상 배지가 필요하나 무엇을 넣을지 결정 필요.
- **검토한 대안**: crates.io 버전 배지 — 크레이트가 crates.io에 게시되지 않아
  깨진 배지가 됨. docs.rs 배지 — 동일한 이유로 제외.
- **선택과 근거**: 실제로 동작하는 것만: GitHub Actions CI 배지
  (`.github/workflows/ci.yml` 존재 확인), MIT 라이선스 배지(`LICENSE`·
  `Cargo.toml`의 `license = "MIT"` 확인), MSRV 배지(`rust-version = "1.88"`).
