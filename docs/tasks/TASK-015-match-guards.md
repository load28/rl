## 목적

태그뿐 아니라 페이로드 값으로도 분기하는 로직을 match 한 곳에 모을 수 있게
Rust 스타일 암 가드를 추가한다. 지금은 삼항 중첩이나 암 본문 안의 if로
밀어내야 해서 분기 구조가 흩어진다.

## 범위

- 포함: 태그 패턴(or-패턴 포함) 뒤 `if <식>` 가드 문법, 가드 있는 match의
  if-체인 방출(라벨 블록으로 switch break 의미 재현), 중복 암 규칙 완화
  (가드 암은 같은 태그 반복 허용), 소진성 검사에서 가드 암 제외,
  3계층 테스트, 레퍼런스 갱신.
- 제외: 와일드카드 가드(`_ if c`) — 파싱하지 않아 원문 통과. `if let` 등
  다른 조건 구문.

## 의사결정

### 결정 1: 가드가 있으면 그 match만 if-체인으로 방출

- **상황**: switch 폴스루로는 "가드 실패 시 다음 암 시도"를 표현할 수 없다.
- **검토한 대안**: ① 모든 match를 if-체인으로 통일 — 가드 없는 기존 방출
  형태(스냅샷·문서에 규범으로 명시)가 전부 바뀜. ② `switch (true)` 트릭 —
  바인딩을 조건식 안에서 쓸 수 없어 가드가 페이로드를 참조하지 못함.
  ③ 가드가 하나라도 있는 match만 if-체인, 나머지는 기존 switch 유지.
- **선택과 근거**: ③. 기존 출력·문서·테스트가 그대로 유효하고, 새 형태는
  가드를 쓴 코드에만 나타난다. 각 암은
  `if (kind 검사) { 바인딩; if ((가드)) return (본문); }` — 가드 실패 시
  블록을 빠져나와 다음 암 검사로 이어져 Rust의 상단→하단 의미와 일치한다.

### 결정 2: 블록 본문 탈출은 라벨 블록 `$rl_b: { ... }` + `break $rl_b`

- **상황**: switch의 `break`는 "값 없이 암 종료"(undefined 평가)를 표현하는데,
  if-체인에서는 본문이 return 없이 끝나면 다음 암 검사로 흘러내리는 버그가 됨.
- **검토한 대안**: ① 본문 뒤 `return undefined;` 강제 삽입 — 항상 return하는
  블록의 추론 타입을 `| undefined`로 오염시킴 (기존 switch 방출이 `break`를
  쓰는 이유와 동일한 문제). ② 선택 플래그 변수 — 방출이 복잡하고 느림.
  ③ 암들을 라벨 블록으로 감싸고 블록 본문 끝에 `break $rl_b` 방출 — switch의
  `break`와 1:1 대응.
- **선택과 근거**: ③. 기존 switch 방출의 의미를 정확히 재현한다. 라벨은
  블록 본문 암이 있을 때만 방출해 불필요한 라벨 경고 여지를 없앤다.

### 결정 3: 중복·소진성 규칙 — Rust 규칙 채택

- **상황**: 가드 암은 조건이 거짓일 수 있어 케이스를 "소진"하지 못하고,
  같은 태그의 암이 여러 번 나오는 것이 유의미해진다.
- **검토한 대안**: ① 기존처럼 태그 중복 전면 금지 — 가드의 핵심 사용례
  (`A if c1 => .., A if c2 => .., A => ..`)가 불가능. ② 가드 유무를 반영:
  중복 에러는 "앞선 **무가드** 암이 이미 그 태그를 덮은 경우"(도달 불가)에만,
  소진성은 무가드 암 태그만 케이스 커버로 인정.
- **선택과 근거**: ②. Rust와 동일한 의미론이고 도달 불가능한 암만 정확히
  걸러낸다. enum 식별에는 (가드 포함) 모든 암 태그를 쓰되 커버 판정에는
  무가드 태그만 써서, 전부 가드인 match(`Some(v) if c => v`)도 "빠진 케이스"
  에러로 잡는다.

## 이슈 및 해결

### 이슈 1: 가드 끝의 행 주석이 `=>`/닫는 괄호를 삼키는 문제

- **증상**: `A if c // 주석` 형태에서 방출된 `if ((c // 주석))`의 닫는
  괄호가 주석에 삼켜져 생성물이 깨질 수 있음.
- **원인**: 가드 span을 trim하면 주석 뒤 개행이 사라짐.
- **해결**: 기존 암 본문 방출과 동일한 처리 — 마지막 줄에 `//`가 있으면
  개행을 덧붙여 닫는 괄호를 다음 줄로 내림.
