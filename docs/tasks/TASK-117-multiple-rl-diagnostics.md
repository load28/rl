# TASK-117: 한 파일의 rl 에러를 여러 개 보고한다

- **상태**: 대기
- **시작일**: —
- **완료일**: —
- **커밋**: —

## 목적

`compile()`은 `Result<String, CompileError>`라 rl 수준 에러를 **하나만**
보고한다. 파일에 소진되지 않은 match가 둘이면 에디터는 하나만 보여 주고,
고치면 다음 것이 나타난다 — tsc·rustc와 다른, 눈에 띄게 나쁜 편집 경험이다.

TASK-116(진단 범위)에서 실측 중 확인한 격차이며, 그 태스크의 범위 밖으로 뒀다:
`sema::check`가 `?`로 첫 에러에서 멈추는 구조 자체를 바꿔야 한다.

## 범위

- 포함(예정): sema·val이 에러를 모아 돌려주는 형태로, `compile()`은 첫 에러를
  돌려주는 지금의 공개 계약을 유지하되 여러 개를 얻는 경로(엔진/서버)를 연다.
- 제외(예정): 파서의 무오류 계약 변경. 파서는 지금처럼 에러를 내지 않는다.
