  사후 수정하면 이력의 신뢰성이 떨어진다.

## 의사결정

### 결정 1: 자유 서술 대신 고정 3섹션 구조 채택

- **상황**: "더 상세히"라는 요구를 어떻게 강제 가능한 형식으로 바꿀지 결정 필요.
  기존 템플릿은 "작업 기록" 단일 섹션이라 상세도가 작성자 재량에 좌우됨.
- **검토한 대안**:
  - A. 기존 단일 섹션 유지 + "상세히 쓰라"는 지침만 추가 — 강제력 없음,
    상세도가 다시 재량으로 회귀할 위험.
  - B. 의사결정/작업 내역/이슈 3개 섹션으로 구조 분리 — 섹션이 비어 있으면
    누락이 즉시 보이므로 리뷰에서 잡힘. 작성 비용은 다소 증가.
  - C. ADR(Architecture Decision Record)을 별도 디렉터리로 분리 — 결정 기록의
    표준이지만 태스크와 결정이 문서 2곳으로 흩어져 이 규모에선 과함.
- **선택과 근거**: B. 문서 하나에서 태스크의 전 맥락(왜→무엇→문제→해결)을 읽을
  수 있어야 한다는 원 요구에 부합하고, 빈 섹션이 곧 체크리스트 역할을 해
  강제력이 생긴다. ADR 수준 분리는 프로젝트가 커지면 후속 태스크로 재검토.

### 결정 2: "이슈 없음"도 명시적으로 기록

- **상황**: 이슈 섹션이 비어 있을 때 "이슈가 없었던 것"인지 "기록을 빠뜨린 것"인지
  구분 불가.
- **검토한 대안**: 빈 섹션 허용 vs "없음" 명시 강제.
- **선택과 근거**: "없음" 명시 강제. 누락과 부재를 구분할 수 없으면 기록의
  신뢰성이 떨어진다. 비용은 한 단어라 사실상 0.

### 결정 3: 기존 태스크 문서(001~005)는 소급 개정하지 않음

- **상황**: 새 형식을 기존 완료 문서에도 적용할지 결정 필요.
- **검토한 대안**: 소급 개정 vs 보존.
- **선택과 근거**: 보존. 사용자 요구가 "앞으로"이고, 완료된 기록물을 사후에
  고치면 "당시에 실제로 기록된 것"이라는 이력 가치가 훼손된다. 기존 문서에는
  당시 의사결정이 "작업 기록" 섹션에 이미 남아 있다.
