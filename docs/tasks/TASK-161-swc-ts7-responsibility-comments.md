## 목적

SWC와 TypeScript 7이 중복 검사기가 아니라 서로 다른 컴파일러 계층을 소유한다는
설계 계약을 코드 가까이에 기록한다. TypeScript 7의 설치 정책을 외부 백엔드에
넘기는 의미 판단의 범위와 혼동하지 않게 한다.

## 범위

- 포함: SWC 전체 프로그램 AST, SWC 출력 자가 검사, TypeScript 의미 백엔드의
  모듈 주석과 책임 경계 설명
- 제외: TypeScript 7 필수화 동작, 백엔드 오류 처리 변경, SWC 또는 tsgo 호출 경로
  변경, 테스트 동작 변경

## 의사결정

### 결정 1: 책임 경계를 각 구현 모듈의 상단 주석에 기록한다

- **상황**: 출력 전체를 SWC로 파싱한다는 사실만 보면 TypeScript 7과 중복된
  검증처럼 보일 수 있다. 반대로 TypeScript 7을 필수 설치한다는 정책만으로 모든
  TypeScript 구문 판단까지 외부 백엔드에 넘겨야 한다고 오해할 수 있다.
- **검토한 대안**: 설계 문서에만 기록하면 구현을 읽는 사람이 경계를 놓치기 쉽다.
  `verify_output` 한 곳에만 기록하면 SWC AST가 lowering의 내부 골격이라는 더 큰
  이유가 드러나지 않는다. 관련 모듈 상단에 나누어 기록하면 중복은 조금 생기지만
  각 계층을 수정하는 자리에서 계약을 바로 확인할 수 있다.
- **선택과 근거**: `program_syntax`, `verify`, `typescript` 모듈 상단에 각각 SWC의
  구문 구조 소유, 생성 결과 자가 검사, ts7의 타입 의미 어댑터 책임을 기록한다.
  설치 필수 여부는 가용성 정책이고 책임 이전의 근거가 아니라는 문장을 TypeScript
  백엔드 경계에 둔다.
