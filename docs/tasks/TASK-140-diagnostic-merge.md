## 목적

여러 분석 계층이 만든 진단을 원본 소스 순서로 합치고, 같은 문제의 중복과 복구 과정의 연쇄 진단을 제거한다.

## 범위

- 포함: 진단 정렬·중복 제거, unresolved match의 typed 소진성 억제, 일반 TS 진단의 rl 선언 이름 병기, 회귀 테스트와 문서 갱신
- 제외: 새로운 언어 구문과 진단 규칙 추가

## 의사결정

### 결정 1: 병합 정책을 보고 경계에 둔다

- **상황**: rl·TypeScript·소진성·val 분석이 서로 다른 단계에서 진단을 추가한다.
- **검토한 대안**: 각 생산자를 정렬하면 계층 결합이 늘어난다. 최종 벡터에서 병합하면 생산자는 독립성을 유지한다.
- **선택과 근거**: `report()` 반환 직전에 위치 정렬과 표시 기준 중복 제거를 적용한다.

### 결정 2: unresolved 억제는 match 단위 분석 사실을 사용한다

- **상황**: 오타가 있는 match에 typed 소진성 진단이 뒤따를 수 있다.
- **검토한 대안**: 진단 스팬 추측은 중첩 match에서 모호하다. `MatchAnalysis::has_unresolved`는 이미 정확한 복구 경계다.
- **선택과 근거**: typed coverage를 추가할 때 같은 keyword offset의 분석 사실을 확인한다.

## 이슈 및 해결

### 이슈 1: 최초 native 회귀 입력이 오타의 대상 enum을 확정하지 못했다

- **증상**: 회귀 테스트가 unknown-case 대신 typed 소진성 및 TS2678을 보고했다.
- **원인**: 오타 arm 하나만 있어 hand-written `kind` union 가능성을 배제할 근거가 없었다.
- **해결**: 올바른 이웃 case arm을 함께 둬 enum을 확정하고, 해당 match의 `has_unresolved`로 생성 코드 진단과 typed 소진성을 모두 억제했다.
