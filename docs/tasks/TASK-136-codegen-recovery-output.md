## 목적

rlc가 이미 진단한 중복 enum 케이스와 중복 패턴 바인딩 때문에 방출 TypeScript가 추가 tsc 오류를 내지 않도록 한다.

## 범위

- 포함: 중복 enum 생성자 키와 중복 패턴 바인딩의 회복 방출, 출력·tsc 회귀 테스트
- 제외: 에디터의 TypeScript 진단 필터, 프로젝트 부분 실패, 파서 커밋 모델, 진단 병합

## 의사결정

### 결정 1: 진단은 유지하고 방출물만 회복한다

- **상황**: 다중 진단을 위해 sema 오류가 있어도 codegen은 계속 실행되어야 하지만, 현재 방출물이 tsc 오류를 추가한다.
- **검토한 대안**: 오류가 있으면 방출 전체를 중단하면 typed 진단을 잃는다. 잘못된 항목을 그대로 방출하면 생성 코드가 tsc 오류를 내지 않아야 한다는 계약을 위반한다.
- **선택과 근거**: 최초의 유효한 의미를 보존하고 중복 부분만 안전한 TypeScript로 회복한다. `compile_report`의 기존 다중 진단 계약을 유지하면서 생성 코드 계약도 지킬 수 있다.

### 결정 2: 패턴 암 전체가 하나의 회복 이름 상태를 공유한다

- **상황**: 중복 이름은 한 객체 구조 분해 안뿐 아니라 중첩 패턴의 여러 구조 분해와 튜플 각 원소의 구조 분해 사이에서도 생긴다.
- **검토한 대안**: 각 구조 분해마다 이름을 따로 추적하면 같은 스코프에 중복 `const`가 남는다. 중복 이름을 항상 고정 문자열로 바꾸면 사용자가 같은 이름을 썼을 때 다시 충돌한다.
- **선택과 근거**: `BindingRecovery`가 암 전체의 원본 이름·이미 방출한 이름·회복 이름 순번을 소유한다. 원본 이름과 충돌하지 않는 `$rl_discardN`을 생성하므로 중첩·튜플에서도 같은 불변조건을 유지한다.
