## 1. 소스 모델

### 1.1 TypeScript 상위집합

`.rl` 파일은 TypeScript 파일에 딱 두 구문 — rl `enum` 선언과 `match` 표현식 —
을 더한 것입니다. 설계 계약:

> **모든 유효한 TypeScript 파일은 그대로 유효한 `.rl` 파일이며, 자기 자신으로
> (바이트 단위 동일하게) 컴파일된다.**

컴파일러는 소스를 한 번 훑으며 두 구문의 후보를 찾고, **후보 구문 전체가
완전하게 파싱될 때만** 변환합니다. 파싱이 한 지점이라도 어긋나면 그 텍스트는
원문 그대로 통과합니다. 따라서 `match`라는 이름의 메서드, `"enum"`이 들어간
문자열, TypeScript 자체의 모든 `enum` 형태는 절대 변형되지 않습니다.

### 1.2 스캔 규칙

변환 루프는 다음 영역을 인식하고 그 내부에서는 rl 구문을 찾지 않습니다:

| 영역 | 처리 |
|------|------|
| `//` 줄 주석, `/* */` 블록 주석 | 그대로 복사 |
| `'...'`, `"..."` 문자열 (이스케이프 인식) | 그대로 복사 |
| 정규식 리터럴 (직전 토큰 기반 휴리스틱으로 나눗셈과 구분) | 그대로 복사 |
| `` `...` `` 템플릿 리터럴 | 텍스트는 그대로, **`${ ... }` 보간 내부는 재귀적으로 변환** |

즉 템플릿 보간 안의 `match`는 변환되고, 문자열·주석 안의 `match`/`enum`은
건드리지 않습니다.

정규식 휴리스틱: `/`는 직전의 유의미한 토큰이 정규식을 허용하는 위치(줄 시작,
`( , = : [ ! & | ? { } ; ~ + - * % ^ < >` 뒤, 또는 `return`·`typeof`·`case`
등의 키워드 뒤)일 때만 정규식 리터럴로 스캔됩니다.

### 1.3 인코딩

스캐너는 바이트 단위로 동작합니다. 판단에 쓰이는 문자는 전부 ASCII이고,
UTF-8 연속 바이트는 어떤 ASCII 비교와도 일치하지 않으므로 멀티바이트 문자
(주석·문자열·식별자 아닌 위치의 유니코드)는 불투명하게 통과합니다.
rl 구문 안의 식별자(케이스 태그, 필드명, 바인딩)는 **ASCII 식별자**
(`[A-Za-z_$][A-Za-z0-9_$]*`)만 지원합니다. 유니코드 식별자를 쓴 구문은
완전 파싱에 실패하므로 원문 통과합니다(에러가 아님).

### 1.4 에러 위치

모든 rl 수준 에러는 원본 `.rl` 소스 기준 `파일:행:열`(1-기반, 열은 UTF-8 코드
포인트 단위)로 보고됩니다. 전체 목록은 [`errors.md`](./errors.md) 참조.

## 2. `enum` 선언

### 2.1 문법

```
rl-enum      ::= "export"? "enum" 식별자 제네릭? "{" 케이스-목록 "}"
케이스-목록  ::= 케이스 ("," 케이스)* ","?
케이스       ::= 태그                         // 유닛 케이스
               | 태그 "(" 필드-목록? ")"      // 페이로드 케이스 (빈 괄호 허용)
필드-목록    ::= 필드 ("," 필드)* ","?
필드         ::= 이름 "?"? ":" 타입
```

- **태그·이름**은 예약어([§4](#4-예약어))가 아닌 ASCII 식별자.
- **제네릭**은 `<`부터 짝이 맞는 `>`까지 원문 그대로 보존됩니다. 제약·기본값
  (`<T extends string, U = number>`)과 `const`/`in`/`out` 한정자를 지원합니다.
- **타입**은 임의의 TypeScript 타입 표기입니다. 최상위 수준의 `,` 또는 닫는
  괄호가 나올 때까지 스캔하며, 괄호 짝·문자열·주석·`=>`를 인식하므로 함수
  타입, 제네릭 타입, 객체 타입 모두 쓸 수 있습니다.
- 각 자리의 공백·주석은 자유롭게 허용됩니다. 후행 콤마도 허용됩니다.

### 2.2 rl enum 판별 규칙

`enum` 선언은 다음 **둘 중 하나 이상**을 만족할 때만 rl enum으로 변환됩니다:

1. 케이스에 페이로드 괄호 `(...)`가 하나라도 있다 — 빈 괄호 `Tag()`도 포함.
2. 선언에 제네릭이 있다 — `enum Option<T> { ... }`.

그 외의 모든 `enum`은 순수 TypeScript enum으로 **바이트 그대로 통과**합니다.
추가로 다음은 무조건 TS의 것으로 취급되어 rl 파싱을 시도조차 하지 않습니다:

- `const enum`, `declare enum` (직전 키워드가 `const`/`declare`)
- `.enum` — 직전 유의미 바이트가 `.`인 프로퍼티 접근

이 규칙이 안전한 근거: TS enum 멤버는 `Ident` 또는 `Ident = 초기화식`뿐이라
`Tag(...)` 형태가 될 수 없고, TS enum은 제네릭을 가질 수 없습니다. 따라서
유효한 TypeScript가 rl enum으로 오인되는 경우는 없습니다.

**유닛 케이스만 필요한데 rl 의미론(태그드 유니언 + match)을 원하면** 한
케이스에 빈 괄호를 붙여 표시합니다:

```rl
enum Color { Red, Green, Blue }        // TS enum — 그대로 통과
enum Status { Active(), Inactive }     // rl enum — Active는 유닛 케이스와 동일하게 동작
```

주의: `Active()`처럼 빈 필드 목록을 가진 케이스는 방출 코드에서 유닛 케이스와
동일하게 `{ kind: "Active" } as const` 싱글턴으로 취급됩니다(§2.3 참조 —
필드가 없으므로 생성자 함수가 아닌 값).

### 2.3 컴파일 결과

하나의 rl enum은 **같은 이름의 타입 별칭과 생성자 객체** 두 선언으로
컴파일됩니다. `export`가 있으면 둘 다 export됩니다.

입력:

```rl
export enum Shape {
  Circle(radius: number),
  Rect(width: number, height: number),
  Point,
}
```

출력:

```ts
export type Shape =
  | { kind: "Circle"; radius: number }
  | { kind: "Rect"; width: number; height: number }
  | { kind: "Point" };
export const Shape = {
  Circle: (radius: number): Shape => ({ kind: "Circle", radius }),
  Rect: (width: number, height: number): Shape => ({ kind: "Rect", width, height }),
  Point: { kind: "Point" } as const,
};
```

규칙:

- **판별 필드는 항상 `kind`**이며 값은 케이스 태그 문자열 리터럴입니다.
- 필드가 있는 케이스 → 같은 이름·같은 순서·같은 선택성(`?`)의 매개변수를 받아
  객체를 만드는 화살표 함수. 반환 타입은 enum 타입입니다.
- 필드가 없는 케이스(괄호 없음 또는 빈 괄호) → `{ kind: "Tag" } as const`
  싱글턴 값. `as const`로 `kind`가 리터럴 타입으로 유지됩니다.
- 제네릭 enum의 생성자는 선언의 제네릭을 그대로 이어받습니다:

```ts
export type Option<T> =
  | { kind: "Some"; value: T }
  | { kind: "None" };
export const Option = {
  Some: <T>(value: T): Option<T> => ({ kind: "Some", value }),
  None: { kind: "None" } as const,
};
```

제네릭 유닛 케이스(`Option.None`)의 타입은 `{ kind: "None" }`이므로 모든
`Option<T>`에 대입 가능합니다.

### 2.4 정적 검사

rl enum으로 판별된 선언에는 다음 검사가 적용됩니다 (전부 rlc 컴파일 에러):

- **중복 케이스** — 같은 태그가 두 번 나오면 에러.
- **필드 타입 검증** — 각 필드의 타입 표기를 swc TypeScript 파서로 파싱해,
  문법이 잘못된 타입을 원본 위치와 함께 거부합니다. `--no-verify`
  (라이브러리에서는 `Options { verify: false }`)로 끌 수 있습니다.

또한 파일 내 rl enum의 (이름 → 케이스 태그 목록)이 심볼 테이블에 등록되어
match 소진성 검사([§3.6](#36-소진성-검사))에 쓰입니다.

## 3. `match` 표현식

### 3.1 문법

```
match-식   ::= "match" "(" 식 ")" "{" 암-목록 "}"
암-목록    ::= 암 ("," 암)* ","?
암         ::= 패턴 "=>" 본문
패턴       ::= 태그                        // 유닛 패턴
             | 태그 "(" 바인딩-목록? ")"   // 필드 바인딩
             | "_"                         // 와일드카드 — 반드시 마지막 암
바인딩-목록 ::= 바인딩 ("," 바인딩)* ","?
바인딩     ::= 필드명                      // 같은 이름으로 바인딩
             | 필드명 ":" 별칭             // 이름 바꿔 바인딩
본문       ::= 식                          // 표현식 본문 (최상위 "," 전까지)
             | "{" 문장* "}"               // 블록 본문
```

- **스크루티니 괄호는 필수**이고 내용이 비어 있으면 안 됩니다.
- 식별자 `match`가 `.` 뒤에 오면(`str.match(...)`) rl match가 아닙니다.
- 위 문법으로 완전히 파싱되지 않는 텍스트는 원문 통과합니다 — `match`라는
  함수 호출, `String.prototype.match` 등 기존 TS 코드는 안전합니다.

### 3.2 의미

`match`는 **표현식**입니다. 스크루티니를 한 번 평가해 그 값의 `kind` 필드로
분기하고, 선택된 암의 값으로 평가됩니다. rl `enum`이 만든 값뿐 아니라
**`kind` 문자열 필드를 가진 모든 태그드 유니언**에 쓸 수 있습니다.

바인딩은 Rust와 달리 **위치가 아닌 이름 기준**입니다. `Tag(field)`는 페이로드
객체에서 `field` 프로퍼티를 구조 분해하는 것이므로, 선언된 필드명과 일치해야
하며(불일치 시 tsc 에러), 일부 필드만 바인딩해도 되고 순서도 무관합니다.
`Tag(field: alias)`는 `alias`라는 이름으로 바인딩합니다.

암 검사 규칙 (rlc 컴파일 에러):

- 같은 태그의 암이 두 번 나오면 **중복 암** 에러.
- `_` 암은 반드시 마지막이어야 합니다.

### 3.3 본문 형태

- **표현식 본문**: `Tag => 식`. 식은 최상위 수준 `,` 또는 닫는 괄호 전까지
  스캔됩니다. 객체 리터럴을 바로 돌려주려면 화살표 함수처럼 괄호가
  필요합니다: `Tag => ({ a: 1 })`.
- **블록 본문**: `Tag => { ... }`. 값을 내려면 `return`을 사용합니다.
  `return` 없이 끝나면 그 암의 값은 `undefined`입니다.

본문 내부는 재귀적으로 변환되므로 **match 중첩**, 본문 안의 rl 구문, 템플릿
보간 내 사용이 모두 지원됩니다.

### 3.4 컴파일 결과

`match`는 `kind`를 판별하는 `switch` IIFE로 컴파일됩니다.

입력:

```rl
const area = match (shape) {
  Circle(radius) => Math.PI * radius * radius,
  Rect(width: w, height) => w * height,
  Point => 0,
};
```

출력 (형태):

```ts
const area = ((() => {
  const $rl_m = (shape);
  switch ($rl_m.kind) {
    case "Circle": { const { radius } = $rl_m; return (Math.PI * radius * radius); }
    case "Rect": { const { width: w, height } = $rl_m; return (w * height); }
    case "Point": { return (0); }
    default: { throw new Error("rl match: unexpected case " + JSON.stringify($rl_m)); }
  }
})());
```

규칙:

- 스크루티니는 `$rl_m` 지역 상수에 한 번만 평가되어 담깁니다.
- 바인딩은 각 case 첫머리의 `const { ... } = $rl_m;` 구조 분해로 방출됩니다.
- 표현식 본문은 `return (식);`으로, 블록 본문은 블록을 그대로 넣고 `break;`로
  끝납니다. `break`를 쓰는 이유: 항상 `return`하는 블록 뒤에 도달 불가능한
  `return`을 덧붙여 match 전체의 추론 타입이 `undefined`로 넓어지는 것을
  막기 위해서입니다.
- `_` 암은 `default` 분기가 됩니다. `_` 암이 없으면 방출되는 `default`는
  위와 같은 **순수 런타임 가드**입니다 — 타입 시스템을 우회해 들어온 값
  (외부 입력 등)에 대한 fail-fast이며, 타입 수준 검사가 아닙니다.

### 3.5 `await`와 async

스크루티니 또는 어느 암 본문에든 `await` 토큰이 있으면(문자열·주석 제외,
템플릿 보간 내부 포함) IIFE가 async로 방출되고 전체가 `await`됩니다:

```ts
(await (async () => { ... })())
```

따라서 async 함수 안에서 `match` 암에 `await`를 자연스럽게 쓸 수 있습니다.
주의: 감지는 토큰 단위이므로 **중첩된 비동기 함수 안에만** `await`가 있는
암도 async로 감싸집니다. 이 경우 바깥 컨텍스트가 async가 아니면 생성물이
문법 에러로 드러납니다 ([§5](#5-제한사항)).

### 3.6 소진성 검사

`_` 없는 match는 rlc가 직접 소진성을 검사합니다 — tsc에 위임하지 않습니다.

알고리즘 (파일 전체 변환이 끝난 뒤 실행되므로 **선언 순서 무관**):

1. 파일 안의 rl enum 선언이 (이름 → 케이스 태그 목록)으로 수집되어 있습니다.
2. `_` 없는 각 match에 대해 **후보 enum** = 암 태그 전부를 케이스로 포함하는
   enum들.
3. 후보 중 하나라도 케이스가 전부 커버되면 통과.
4. 후보가 있는데 전부 미달이면 에러 — 빠진 케이스가 가장 적은 후보를 골라
   `match on enum E is not exhaustive: missing "X"` 형식으로 보고합니다.
5. **후보가 없으면 검사하지 않습니다.** 다른 파일에서 import한 enum이나
   손으로 쓴 태그드 유니언에 대한 match가 여기 해당합니다 — 검사 없이
   컴파일되고, `default` 런타임 가드(§3.4)만 남습니다.

`_` 암이 있는 match는 정의상 소진적이므로 검사하지 않습니다.

검사는 **파일 단위**입니다. import 추적을 통한 프로젝트 단위 검사는
로드맵입니다 ([design 문서](../design/enum-and-error-layers.md) 참조).

다음 단어는 enum 이름, 케이스 태그, 필드명, match 패턴 태그, 바인딩 이름,
별칭이 될 수 없습니다. 파싱 중 이 단어를 만나면 rl 구문 해석을 포기하고
원문 통과합니다 (에러가 아님) — `match (x) { case => 1 }` 같은 텍스트가
기존 TS 코드일 가능성을 지키기 위한 규칙입니다.

## 5. 제한사항

- **소스맵 미생성.** 생성된 `.ts`와 원본 `.rl`의 행이 대체로 대응하지만
  보장되지 않습니다.
- **패턴은 케이스 태그와 `_`뿐.** 리터럴 패턴, 중첩 패턴, `A | B` 패턴,
  가드는 의도적으로 지원하지 않습니다 (최소 기능 유지).
- **소진성 검사는 같은 파일의 rl enum에 대해서만** 동작합니다 (§3.6).
- **표현식 암의 객체 리터럴은 괄호 필수**: `Tag => ({ a: 1 })`.
- **스크루티니 괄호 필수**: `match (x) { ... }`.
- **async 감지는 토큰 단위**: 중첩 함수 안에만 `await`가 있어도 async로
  감싸집니다 (§3.5).
- **`.tsx` 미지원**: 제네릭 화살표 함수 출력(`<T>(...) => ...`)이 JSX 문법과
  충돌할 수 있습니다.
- **rl 구문 안의 식별자는 ASCII만** 지원합니다 (§1.3).
- **`--no-verify` 사용 시** 필드 타입 오류가 컴파일 시점에 잡히지 않고
  생성물에 그대로 전파되어 tsc 단계에서 드러납니다.
